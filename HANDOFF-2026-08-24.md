## 4. Navigation now has three independent safety nets

The owner reported the landing CTA dead across roughly six rounds while it was
live and correct on production the whole time. The cause was a long-lived tab
running an older build. All three layers are verified inside the deployed bundle:

1. **CTA fallback** (`LiveUnitCount.jsx`): routes via the router, then 260ms
   later checks `location.pathname` and does `window.location.assign()` if the
   URL did not move.
2. **`ChunkErrorBoundary`**: reloads once for **any** caught error. The original
   `isChunkError()` gate was removed after the owner reached the fallback
   message on a real stale-chunk failure, which proved the matcher missed what
   the browser actually threw.
3. **Build-version guard**: `npm run build` writes `dist/version.json` with the
   entry bundle's hashed filename; `BuildVersionManager` compares it on arrival
   and on every route change and reloads once if they differ.

🔑 **Before debugging any "it is still broken" report, run this:**

```bash
curl -s https://www.irfaninvest.com/version.json
curl -s https://www.irfaninvest.com/ | grep -oE 'src="/assets/index-[^"]+"'
```

If they match, production is current and the reporter is on a cached tab. Grep
the live bundle for the code you shipped rather than trusting the browser pane,
which is unreliable in this environment.

## 5. Analytics was lying about three languages

`resolvePage()` in `src/analytics.js` matched logical paths but never stripped
the language prefix, so `/fa/insights/<slug>` fell through to the default and
GA4 recorded `page_title "خانه | FA"`, `content_group "Home"`. **Every ar, ru
and fa article, project page and landing was filed as a homepage view.**

Fixed 2026-08-22. ⚠️ **Corrects collection from that date forward only.**
Historic ar/ru/fa data stays mis-attributed and cannot be rewritten.

To read per-article views: GA4 (`G-P2PTCKJKYK`) → Reports → Engagement → Pages
and screens → dimension **Page path and screen class** → search `insights`.
Content group **Blog** isolates all articles at once.

## 8. The fa-only UAE landing

`/fa/oman-property-for-iranians-in-uae` targets «خرید ملک در عمان برای ساکنین
امارات» (note **ساکنین**, not مقیم). No competitor page contains that phrase at

body in the prerendered shell, and 69 fa pages link it.

🆕 Two mechanisms were built for it and both are reusable:
- `seoRoutes.mjs` entries can carry `langs: [...]`, honoured by
  `prerender-routes.mjs` and `api/sitemap.js`, so a route can exist in one
  language only. fa 200, bare/ar/ru **404 by design**.
- `footerSeoLinks.mjs` SERVICES entries can carry `langs` too. **Always map via
  `servicesFor(lang)`, never `SERVICES` directly** to mapping it raw puts an
  empty-label anchor pointing at a 404 on every non-fa page.

## 9. Things that will bite

- **The vercel.json route allowlist.** Adding a `<Route>` without adding its
  rewrite makes the page 404 in production.
- **478 vs 373 is not a bug.** The landing counter counts UNITS; `/project`
  collapses near-identical units into one card. If you change one, change the
  other, and the sub-line copy explains it.
- **`src/data/iraniansUaeContent.mjs` quotes the unit count AND the price-index
  median**, so it is part of every inventory refresh.
- **Deploys build server-side on Vercel**, so local `dist/assets/*` hashes
  differ from production. Testing a local hash against prod gives a false 404.
- No em dashes in any client-facing copy.
- No yield or ROI claims. There is no rent data in the database, and the public
  Oman yield figures are inconsistent and cover a different market (older
  Muscat city stock, not our ITC communities).

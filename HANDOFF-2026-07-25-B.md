### Two data traps — read before touching the maths
1. **`project_units.price_per_sqm_omr` is unusable.** NULL for 87 of 395, and
   where filled it disagrees with itself: Vistal stores hand-rounded marketing
   rates (2,000 / 2,300 / 2,600) 5-19% above the arithmetic. The index
   computes `price / total_area` instead, which is also the only definition a
   reader can reproduce from our own unit pages.
2. **`total_area_sqm` follows two conventions.** Wadi Zaha records the plot
   *alongside* a covered-only total (`total == internal`); Hawana Salalah and
   Jebel Sifah *fold it in*. Dividing by the latter gave **297 OMR/m² next to
   a 950 median**. `isPlotDominant()` needs **both** `total > internal` **and**
   `garden/total > 50%` — a garden-share test alone wrongly excludes the seven
   Wadi Zaha villas. Catches exactly 5 units, excluded from per-m² columns
   only, and the exclusion is stated on the page with its live count.

### Three mapbox traps found the hard way
1. **`fitBounds()` right after `new mapboxgl.Map()` is silently ignored** —
   the map stays on its initial centre/zoom. With Salalah ~700 km from Muscat
   that projected pins ~4,800 px outside the container AND stretched the
   document into a horizontal scrollbar. Fit on `'load'` (`isStyleLoaded()`
   check) + `map.resize()` + a `setTimeout` backstop, never rAF.
2. **Never transition `transform` on a marker element.** Mapbox writes
   `transform: translate(...)` onto it on every map move, so a
   `transition: transform .16s` added for a hover scale made each pan animate:
   pins visibly lagged the map and eased back onto their point. Split into a
   `.smap-marker` root mapbox owns (no transform transition) wrapping a
   `.smap-pin` pill that carries the motion.
3. **A style edited in Mapbox Studio does NOT reach the site by itself.** The
   code hardcoded the Mapbox-owned `mapbox/dark-v11`, which nobody can edit or
   publish. Now all four maps read `src/lib/mapStyle.js` →
   **`VITE_MAPBOX_STYLE`**, fallback `dark-v11`.
   Live value: `mapbox://styles/amirreza1997/cmpjnz4o5000i01sb4w096q3h`
   (imports `mapbox/standard`, `theme:default`, `lightPreset:night` → still
   dark, so the white pills keep contrast; needs mapbox-gl v3+, we run 3.24).
   `VITE_*` inlines at BUILD time → changing it needs a **redeploy**.

## 4. Em dashes removed everywhere

Client rule: the copy must not read as AI-written. **197 in source strings**
across 12 files + **291 in the blog DB** across 47 of 119 articles. Verified
**0 across all 615 built HTML pages**.

- Title separator `X — Y | Brand` → `X: Y | Brand`; prose rewritten **per
  case**; ar/fa → `،`, ru → `,`; table empty-cell → en dash `–`.
- 🔑 **Russian is the trap**: the dash often carries the verb "to be"
  (`X — это Y`), so a comma makes it ungrammatical. ~12 lines needed real
  rewrites. Always eyeball the ru diff.
- `index.html` needed direct fixes too: the JSON-LD org description and the
  boot-splash `taglines.ru` are served content.
- ⚠️ Watch i18n strings **concatenated after a bold name**
  (`cardOneBody`/`cardTwoBody` start with their own separator) — stripping a
  leading `' — '` glues words together.
- Code comments and build `console.log`s deliberately left alone.

### 🚨 The insights-admin incident — read before ANY blog write
`insights-admin`'s `upsert` runs `sanitizeRow()`, which builds a **complete**
row with hardcoded defaults (`cover_image:null`, `category:null`,
`published:Boolean(input.published)` → **false**) and then does a full-column
`update`. **Sending a partial row silently blanks every column you omit.**
Sending `{id, slug, lang, body_md}` to 47 rows unpublished all 47 and nulled
their cover/category/excerpt/seo fields.
- **ALWAYS send the WHOLE row.** `title` is the only field it hard-rejects
  (400), so a missing title is the *lucky* failure.
- Nothing is ever deleted — a "dropping" row count is RLS: the anon key only
  sees `published=true`. Diagnose with service-role SQL, not REST.
- Recovered fully: content from a pre-write REST snapshot, `cover_image` from
  `og:image` and `category` from the styled `<p>` in the **pre-damage `dist/`
  build**. Verified 119/119 published, 0 nulls, 0 content lost.

**n8n**: the prompt already said "never use em-dashes" and Fable-5 ignored it,
which is how 291 accumulated. A prompt is a request, not a guarantee — there
is now a `stripEmDash()` pass in the **`Finalize row`** code node, the last
transform before saving, so it also catches what the OpenAI SEO editor
reintroduces. Published, activeVersionId `b6e62947`.

## 6. Gotchas that cost real time this session

1. **`git push` does NOT deploy this project.** Vercel is not connected to the
   repo. Worse, `/property-prices-in-oman` answered **200** before it existed —
   the `vercel.json` catch-all serves the SPA shell for any unknown URL, so a
   status code proves nothing. Verify with the `<title>` or the sitemap count,
   and deploy with `vercel deploy --prod --yes`.
2. **Local build hashes ≠ production hashes.** Vercel builds server-side, so
   `curl`ing a local `dist/assets/Foo-<hash>.js` name against prod 404s. Follow
   the module graph from the page instead.
3. **The browser pane runs hidden.** rAF, CSS animation, IntersectionObserver
   and mapbox rendering are all suspended; screenshots below the fold come back
   solid black (dark pages) or white (the light page), the viewport sometimes
   reports 0×0, and mapbox requests **zero tiles**. Verify via DOM and computed
   styles; call `resize_window` with explicit width/height before measuring
   geometry. For mapbox, the trustworthy signal that a style loaded is that the
   app fetched `…/styles/v1/<owner>/<id>` **and its `/iconset.pbf`**.
4. Vite serves two dep-optimization generations at once after a dep change and
   throws a bogus **"Invalid hook call / more than one copy of React"**. A hard
   reload clears it. Not a code bug.
